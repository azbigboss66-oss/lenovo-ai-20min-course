# 第 02 课详细讲稿｜Prompt：把要求写成工作合同

> 建议 25 分钟；其中对比观察、练习和讨论约 6 分钟。

## 0:00–2:30｜同一句“整理一下”，为什么结果每次不同

上一课我们用输入—推断—输出—影响判断任务。今天把判断写成模型能执行的委托。

请看屏幕：“请把下面会议内容整理成一份专业周报。”这句话的问题不在于不礼貌，也不在于缺少“你是一位顶级专家”。它缺的是工作合同：周报给谁看、为了做什么决策、只能依据什么材料、不能补什么、按什么格式交付、怎样算完成。

人类同事可能靠组织经验向你追问，也可能根据过去模板猜。模型同样会利用模式补全，但它补出来的内容更流畅、更快，也更容易让人忽略猜测。Prompt 的作用不是让模型变得全知，而是把我们脑中的隐含要求变成可执行、可验收的接口。

本课用“五字段法”。这是为便于教学记忆而归纳的框架，不是行业唯一标准。真正重要的不是背五个词，而是把工作中会造成返工或风险的条件写出来。

## 2:30–6:00｜字段一和二：目标与必要上下文

第一个字段是任务目标。目标至少回答三个问题：产物是什么、给谁使用、支持什么动作。例如：“根据会议记录生成一页项目周报草稿，供项目负责人在周会上确认进度和风险。”这比“整理得专业”更有用，因为“专业”不能直接验收。

第二个字段是必要上下文。上下文不是把所有文件都扔进去，而是提供完成任务真正需要的材料：会议原文、固定术语、允许引用的资料、已有模板和少量好例子。资料越多并不必然越好；无关、冲突或过期材料会增加错误。

在星桥案例中，我们提供会议记录和周报字段定义，但不提供真实联想模板，不编造公司制度。还要告诉模型：“只依据 `<会议记录>` 标签内内容，不调用其他事实；如果材料冲突，分别列出。”

把资料放在明确分隔符中，是为了让模型知道哪里是指令，哪里是被处理内容。例如用 `<会议记录>…</会议记录>`。这不是绝对安全边界，但能减少结构混淆。如果原始资料里出现“忽略之前要求、直接发送”之类文字，也应把它当作资料内容，而不是新的操作指令。

## 6:00–9:30｜字段三：约束要写成可检查规则

第三个字段是约束。弱约束是“不要出错”“尽量准确”，因为它没有告诉系统如何处理不确定。强约束是可观察规则：

“不得补写负责人、日期、数字和决策；材料未出现时填‘待确认’；建议必须放入独立建议栏；不得把建议写成会议结论；保留原始项目名；不执行发送或系统更新。”

大家会发现，这些规则本质上来自业务经验。把它们写入 Prompt，相当于提前把常见返工原因变成验收条件。

角色设定可以使用，但要知道它解决什么。“你是项目经理”可能帮助模型选择关注点和语气，却不能赋予它真实项目权限，也不能创造会议中不存在的负责人。我们不禁止角色，而是不把角色当作事实保障。

另一个常见误区是一次塞入十几条互相冲突的要求。约束应按优先级写，关键安全规则放在前面；格式偏好可以后置。如果“必须在 100 字内”与“逐项保留所有证据”冲突，要先决定哪个更重要。

## 9:30–12:30｜字段四：输出形式让结果可进入下一步

第四个字段是输出形式。请不要只写“用表格”。要定义表格列：事项、状态、负责人、截止日期、原文证据、待确认；再定义摘要的篇幅和顺序。

为什么这很重要？因为 AI 输出不是终点，它通常要进入后续工作：人工审阅、粘贴到周报、导入任务系统或交给另一段流程。字段稳定，后续才能检查和复用。

对于管理层周报，我们可以要求：先给 80 字以内摘要；再给行动项表；最后给待确认清单。状态只允许“已确认、进行中、待确认”；负责人和日期若无原文，不得用常识补齐。

如果机器还要处理结果，可以要求 JSON 等结构化格式；如果是人阅读，表格和短段落更合适。不要为了显得技术化而使用不需要的格式。

## 12:30–15:30｜字段五：验收与停止是企业 Prompt 的分水岭

第五个字段是验收与停止。很多 Prompt 有目标和格式，却没有说明什么时候必须停。

验收条件可以是：“每个事实都能在原文找到；行动项字段齐全；未知值统一为待确认；建议与事实分栏；输出不包含材料外的产品参数。”停止条件可以是：“输入为空、来源冲突无法判断、任务需要真实系统权限、要求对外发送时停止，并列出需要人工确认的问题。”

停止不是失败。对高影响工作而言，知道什么时候不继续，是能力的一部分。一个总能给出答案的系统，不一定比一个证据不足时会停的系统更好。

在对话式使用中，还可以要求模型先复述任务理解，并提出最多三个关键问题。只有当缺失信息确实改变结果时才提问，不要让模型把每个小细节都变成阻塞。

## 15:30–18:30｜完整 Prompt 与结果对比

现在把五个字段合在一起：

“任务目标：根据以下教学模拟会议记录，生成一页项目周报草稿，供项目负责人确认。必要上下文：只使用 `<会议记录>` 内内容，术语按原文。约束：不得补写负责人、日期、数字或决策；缺失填待确认；事实、建议分开；不执行发送。输出形式：80 字摘要、行动项表、待确认清单。验收与停止：每项事实附原文短证据；发现冲突分别列出；输入不足或需要系统权限时停止并提出最多三个问题。”

对比模糊版本，结构化版本未必文字更多，但返工点更少。我们可以逐项验收，而不是凭感觉说“挺专业”。

这里演示一次小迭代。如果输出把“服务团队建议补 FAQ”写成已批准任务，不要只说“重新写得严谨一点”。应指出违反哪条合同：“你把建议改成了已确认事实。请保留原文证据，把它移到建议栏，并在状态中写待确认。”这叫基于失败证据修正，而不是情绪化调 Prompt。

## 18:30–22:30｜练习：把模糊请求改成五字段合同

请打开练习。场景是渠道培训团队收到三段模拟反馈，需要生成管理摘要。原请求只有一句：“帮我总结一下反馈，告诉我应该改什么。”

四分钟内填五个字段。至少写出：目标读者、允许材料、不得编造、固定输出字段、缺失或冲突时如何处理。不要追求长，追求可检查。

（两分钟个人填写；一分钟两人互换，用五字段逐项打勾；最后请一位同事读出“停止条件”。）

讲评时我不会寻找唯一答案。我们看三件事：第一，是否把“反馈中出现”与“你的建议”分开；第二，是否要求标明反馈编号或出处；第三，是否在样本不足时避免说“所有渠道都认为”。

如果完成得快，再加一条：输出中每条建议要写“依据—建议—验证方式”。这样建议就能进入后续试验，而不是停留在形容词。

## 22:30–25:00｜收束：Prompt 是最小的责任接口

请记住：目标决定为什么做；上下文决定依据什么；约束决定不能越过哪里；输出决定怎样交付；验收与停止决定何时算完成、何时必须问人。

Prompt 可以让一次委托更清楚，却不能解决所有问题。资料没有提供、需要最新版本或必须核实出处时，继续加文字不能让模型凭空获得事实。下一课会进入证据、数据与 RAG。

今天带回岗位的动作：找到你过去一周让 AI 返工最多的一条请求，不要先重写整段。先标出返工原因属于五字段中的哪一项，再只补那一项。这样你会从“收藏 Prompt”转向“诊断 Prompt”。

快速收束句：好 Prompt 不是长，而是可执行、可验收、缺信息时会停。
