# PPT 页纲：从一句话到一种能力

## 使用原则

- 共 11 页内容页和 1 页课后来源附录，按 16:9 制作。
- 每页标题是一句可独立成立的结论，不使用“背景”“Prompt 介绍”等主题词标题。
- 屏幕只放结论和证据，详细解释来自讲稿与备注。
- 建议白底、黑灰文字、联想红仅用于关键路径或风险，不使用渐变、装饰卡片和密集图标。
- 所有案例角落固定显示“教学模拟｜不代表联想真实流程”。

## 第 1 页｜0:00–0:40

### 结论标题

**AI 能力不是会聊天，而是把工作变成可验证结果**

### 屏幕内容

中央只显示一句原始请求：

> 把下面会议内容整理一下。

底部小字：20 分钟路径——理解模型 → 写清 Prompt → 封装 Skill → 评测后升级。

### 视觉证据

一条由浅到深的四阶段路径，当前停在“模糊请求”。不放机器人插画。

### 讲者提示

告诉听众本课不要求代码，用每天都见过的协作任务贯穿。对应讲稿 0:00–0:40。

## 第 2 页｜0:40–2:00

### 结论标题

**同一段会议记录，会因任务合同不同得到完全不同的结果**

### 屏幕内容

左：`整理一下`。

右：`给谁 + 只用什么 + 输出什么 + 缺失怎么办 + 如何验收`。

底部用红框标出两个虚构值：`下周一`、`周三前`。

### 视觉证据

前后对照：左侧为流畅但含虚构日期的三行结果；右侧为有依据列和“未提供”的结构化结果。

### 讲者提示

让听众找出两个原文没有的信息。对应讲稿 0:40–2:00。

## 第 3 页｜2:00–3:10

### 结论标题

**AI 系统从输入中推断输出，并通过输出影响工作环境**

### 屏幕内容

`输入 → 推断 → 输出 → 影响`

下方三类输出：预测｜内容｜建议/决策。

### 视觉证据

一条四节点流程。每个节点下用主案例填入：会议记录、模型处理、周报、项目判断。

### 来源

OECD AI system definition, 2023。[2]

## 第 4 页｜3:10–4:40

### 结论标题

**大语言模型预测 token，因此能生成，也会把“像真的”写成“是真的”**

### 屏幕内容

上方：`会议 → 记 → 录 → …… → 下一个 token 的概率`。

下方：`流畅 ≠ 有来源 ≠ 可直接决策`。

### 视觉证据

用一行 token 方块连接到三个候选词及概率；旁边用小型注意力连线表示上下文关联。不要画完整神经网络。

### 来源

Google ML Crash Course；Vaswani et al.；NIST。[3][4][5]

## 第 5 页｜4:40–6:20

### 结论标题

**企业使用 AI 要同时检查输入边界和输出证据**

### 屏幕内容

左侧“输入前”：获准工具｜最少必要信息｜脱敏。

右侧“输出后”：事实来源｜人工责任｜错误可发现。

中心转场句：`Prompt 是本次工作的任务合同`。

### 视觉证据

输入闸门和输出闸门，中间是一台抽象模型。案例标注“客户 A”“日期未提供”。

### 来源

NIST；Lenovo Responsible AI。[5][19]

## 第 6 页｜6:20–8:40

### 结论标题

**五个字段把模糊愿望变成可执行、可验收的 Prompt**

### 屏幕内容

五列或五步：

1. 目标——为谁完成什么；
2. 上下文——依据哪些材料；
3. 约束——不能错什么；
4. 输出——交付什么结构；
5. 验收/停止——未知时怎么办。

脚注：课程记忆框架，不是唯一行业标准。

### 视觉证据

每个字段连接一个失败模式：答非所问、混入外部知识、泄露或虚构、格式漂移、证据不足仍继续。

### 来源

OpenAI Prompt engineering。[6]

## 第 7 页｜8:40–10:30

### 结论标题

**“只用原文、缺失写未提供、每项给依据”让结果真正可检查**

### 屏幕内容

只展示主 Prompt 的三句关键合同：

```text
只使用记录中的事实。
负责人或日期缺失时写“未提供”。
每个行动项保留原文依据。
```

右下角放五列表头：事项｜负责人｜日期｜依据｜状态。

### 视觉证据

从原文短句连线到行动项一行，明确显示证据链。

### 讲者提示

进行第一次十秒判断；完整 Prompt 放讲稿和课后材料，不整段贴到 PPT。

## 第 8 页｜10:30–13:40

### 结论标题

**Prompt 解决这一次，Skill 固化这一类任务的过程资产**

### 屏幕内容

左：Prompt——目标、上下文、约束、输出、验收。

右：Skill——触发、步骤、参考资料、脚本、异常、停止、输出合同、版本。

### 视觉证据

展示真实目录轮廓：

```text
meeting-to-action-skill/
├─ SKILL.md
├─ examples/（4 组输入/参考答案）
├─ evals/（断言、结果、追踪）
├─ references/output-contract.md
└─ scripts/（检查、评测、运行器）
```

### 来源

OpenAI Skills；Agent Skills Specification。[7][8]

## 第 9 页｜13:40–15:30

### 结论标题

**一个可靠 Skill 要经历选择、提炼、封装、评测和版本化**

### 屏幕内容

`高频清晰任务 → 观察真实执行 → 拆分资产 → 写异常/停止 → 有无 Skill 对照 → 版本化`

下方：`模型做语义｜脚本查机械规则｜人确认业务事实`。

右下角保留小型证据条：`本地教学快照｜基线 1/4 → Skill 4/4｜n=4`。

### 视觉证据

带反馈箭头的闭环；评测节点展示“代表性样例、边界样例、断言、人工复核、时间/成本”。证据条旁注“授权案例由运行器在模型前停止；不代表生产准确率”。

### 来源

Agent Skills Best Practices and Evaluation。[9][10]

## 第 10 页｜15:30–18:30

### 结论标题

**专业 AI 工程先定位失败层，再用评测决定是否升级**

### 屏幕内容

一张七行阶梯：

| 失败层 | 优先手段 |
|---|---|
| 任务不清 | Prompt |
| 缺事实 | RAG |
| 要操作 | 工具 |
| 流程重复 | Skill/工作流 |
| 步骤不可预知 | Agent |
| 稳定行为缺口 | 微调/LoRA |
| 广泛新能力 | 预训练 |

底部：`微调改变稳定行为，不负责同步最新事实；预训练形成广泛基础能力。`

### 视觉证据

阶梯左侧从应用层上升到基础训练层；一条“评测”纵向贯穿所有层。不要把微调画成终点奖杯。

### 来源

RAG、ReAct、Agent 工程、模型优化、InstructGPT、LoRA、Chinchilla。[11]–[18]

## 第 11 页｜18:30–20:00

### 结论标题

**企业 AI 的专业性，最终体现在可交、可证、可责、可追**

### 屏幕内容

四问各保留一行：

- 可交：材料可以交给当前获准工具吗？
- 可证：关键事实有可访问的来源吗？
- 可责：谁复核，谁作最终决定？
- 可追：资料、版本、检查和结果能追溯吗？

底部收束：`先定义结果，再提供证据；高频任务封装为 Skill；任何升级都由评测证明。`

### 视觉证据

主案例从“模糊请求”经过 Prompt、Skill 和评测，最终穿过四问闸门。只画一条闭环，不再重复七层阶梯。

### 来源

Lenovo Responsible AI。[19][20]

## 信息密度检查

- 内容页标题均为完整结论。
- 第 6 页是唯一五项并列表；第 10 页是唯一完整决策矩阵；第 11 页只负责责任收束。
- 完整 Prompt、详细定义和研究限制留在讲稿与备注，不塞入屏幕。
- 视觉均服务于对比、因果、结构或选择，不使用装饰性图片。

设计方法参考 [Assertion-Evidence Presentations](https://www.assertion-evidence.org/)；完整资料见 [research/sources.md](../research/sources.md)。
