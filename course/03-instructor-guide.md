# 讲师指南

## 受众处理

听众是资深在职同事，不是缺乏工作经验的学生。尊重他们对客户、项目、风险和协作的已有判断，只补充 AI 心智模型和工程方法。开场不要问“大家知道什么是 AI 吗”，而要从熟悉的会议整理任务切入，让业务经验成为理解新概念的支点。

## 授课前准备

1. 阅读 [课程大纲](00-course-outline.md) 和 [详细讲稿](01-speaker-script.md)。
2. 熟悉 [Prompt 前后对照](../examples/prompt-before-after.md)，确认所有姓名和项目均为模拟。
3. 在实际授课环境中核对公司当时批准的 AI 工具、数据输入和内部政策。公开课程材料不能替代这些要求。
4. 从仓库根目录运行 `python -X utf8 examples/meeting-to-action-skill/scripts/evaluate_cases.py`、`python -X utf8 scripts/estimate_timing.py` 和 `python -X utf8 scripts/check_repo.py`。
5. 打开 [本地模型对照](../examples/meeting-to-action-skill/evals/evaluation-results.md)，确认会解释基线 `1/4`、Skill `4/4` 以及小样本边界。课堂优先展示已保存结果；若现场模型失败，立即切回静态输出，不占用课程时间排障。
6. 至少完整彩排一次，记录每段实际用时；优先保证 Prompt、Skill 和技术选择三段。

## 发音与术语

| 术语 | 建议读法 | 一句话解释 |
|---|---|---|
| AI | 英文字母 A-I | 从输入推断输出并影响环境的机器系统 |
| LLM | 英文字母 L-L-M | 用大量参数学习语言模式的大语言模型 |
| token | “托肯”即可 | 模型处理文本的基本片段 |
| Prompt | “普朗普特”或直接说提示/指令 | 本次任务给模型的输入和要求 |
| RAG | 英文字母 R-A-G | 请求时检索外部资料并放入上下文 |
| Skill | “斯基尔”或直接说技能包 | 可复用、可版本化的任务过程包 |
| Agent | “诶真特”或直接说智能体 | 根据环境反馈动态规划并使用工具的系统 |
| fine-tuning | 微调 | 用任务示例调整模型参数层的行为倾向 |
| LoRA | “洛拉” | 冻结基础权重并训练较小低秩更新的高效微调方法 |

不要要求听众记英文全称。英文只用于帮助他们以后阅读产品界面和资料。

## 关键类比及其边界

模型可以类比“读过大量材料、很会续写的同事”，但必须立即补一句：模型没有人的共同经历、责任和数据库式记忆。Prompt 类比工作委托；RAG 类比本次交付的最新资料；工具类比可操作的计算器和业务系统；Skill 类比经过验证的标准作业包；评测类比验收清单；微调类比用大量样例调整稳定习惯。

类比只帮助建立关系，不能替代技术定义。尤其不要说模型“真正理解了会议”或“在数据库里查到答案”。

## 两次互动怎样带

### 第一次：找缺项

问：“如果把这句话交给一个不了解项目的新同事，他至少还需要知道哪两件事？”

接受任何合理答案：给谁看、目的、材料范围、篇幅、格式、不可猜内容、验收方式。不要花时间纠正顺序，随后归并为五字段。

### 第二次：选技术层

先让听众投票 Prompt、RAG、Skill 或微调。答案不是单选技术名，而是顺序：先把合同写清并封装重复流程；需要系统事实时再接检索或工具；评测仍有稳定行为缺口时才讨论微调。

## 常见误解与纠正

| 误解 | 课堂纠正 |
|---|---|
| Prompt 越长越好 | 只写影响结果的目标、材料、边界、接口和验收；简单任务可以很短。 |
| 加一个专家角色就会更准确 | 角色影响语气与视角，不提供事实来源。 |
| RAG 会让模型永不出错 | RAG 补充资料，检索可能漏召回，模型也可能误用；仍需引用和评测。 |
| Skill 就是一段收藏的 Prompt | Skill 还管理触发、资源、脚本、异常、停止、输出合同和版本。 |
| 有 `SKILL.md` 就已经自动运行 | 还需要兼容环境、选择机制、权限、工具、记录和评测。 |
| 微调能记住最新政策 | 微调改变行为倾向；频繁变化的事实更适合受控检索。 |
| 预训练就是更深度的微调 | 预训练形成广泛基础能力，数据、规模和算力工程完全不同。 |
| 自动检查通过就等于业务正确 | 脚本只能检查机械合同；事实、适用性和传播范围仍由人确认。 |

## 讲授语气

- 使用“我们怎样让结果更可用”而不是“大家不会用 AI”。
- 把经验丰富的同事定位为业务验收者和流程设计者。
- 技术概念出现后，十秒内回到联想工作场景。
- 不展示实时联网或厂商界面，避免产品版本、网络和账号干扰主线。
- 不引用或播放视频；所有信息用图、表、文字和口头解释呈现。

## Skill 演示方式

优先展示仓库已保存的正常案例输入、基线输出、Skill 输出和评测结果，不依赖现场模型速度。若要现场运行，只能使用获准环境和教学模拟输入；先运行参考答案评测，再运行本地模型脚本。授权不明案例必须展示追踪中的 `stopped_before_model: true`，说明正文没有发送给模型。

不要只报 `4/4`。完整话术是：“四个教学样例中，模糊基线通过一组，Skill 通过四组；其中授权案例由运行器在模型前停止。这个快照证明过程合同在小样本上改善可检查性，不证明生产准确率。”

## 超时删减顺序

若彩排超过 20 分钟，按以下顺序删减：

1. LoRA 的低秩矩阵细节，只保留“冻结大部分权重、训练较小更新”。
2. Token 的英文拆分示例。
3. Skill 评测中的 token 成本记录。
4. 第二、第三个补充工作案例。

不可删减：模糊 Prompt 对比、五字段、Skill 与 Prompt 区别、停止条件、技术选择表、可交/可证/可责/可追。

## 时间不足时的 15 分钟版本

- 0–2 分钟：开场对比。
- 2–4 分钟：LLM 生成与幻觉。
- 4–8 分钟：Prompt 五字段。
- 8–12 分钟：Skill 结构与制作。
- 12–14 分钟：技术选择矩阵。
- 14–15 分钟：责任四问与收束。

## 现场问题的回答边界

如果有人询问具体联想内部工具是否获准、某类数据能否上传、某系统如何接入或当前审批由谁负责，不要依据本教材猜测。回答：“这取决于当前内部政策和您所在业务的权限，请以公司正式渠道和负责人确认为准。”

如果有人问某个模型是否最好，先追问任务、数据、延迟、成本和验收标准。课程的立场是用代表性评测选择方案，不给出脱离场景的厂商排名。
