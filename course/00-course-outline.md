# 课程大纲：从一句话到一种能力

## 课程定位

- 受众：在联想工作多年、熟悉业务协作，但刚接触生成式人工智能的同事。
- 时长：20 分钟。
- 主案例：把一段跨部门项目会议记录整理成管理层周报与行动项。
- 教学方式：先看完整示例，再做两次快速判断，最后给出可迁移的技术选择框架。
- 内容边界：所有业务材料均为教学模拟；课程不代表联想当前内部工具、制度或审批流程。

## 学习成果

课程结束时，听众应能现场完成四件事：

1. 解释为什么大语言模型能写得流畅，也可能把未知事实补出来。
2. 用五字段法把一句模糊要求改写成可验收 Prompt。
3. 说明 Skill 比“收藏一个好 Prompt”多了哪些工程要素。
4. 根据失败原因选择 Prompt、RAG、工具、Skill、Agent、微调或预训练。

## 内容骨架

### 第一部分：AI 是生成机制，不是事实数据库

只讲七个词：输入、输出、token、上下文、概率、参数、自注意力。Transformer 的网络细节和训练数学留在备课材料，不进入主讲。核心判断是：模型输出首先是一段高概率生成结果，事实正确性需要证据。

### 第二部分：Prompt 把愿望翻译成工作合同

五字段法：

1. **目标**：最终要完成什么，给谁使用。
2. **必要上下文**：原始材料、背景、允许使用的来源。
3. **约束**：不能做什么，必须保留什么，语言和篇幅边界。
4. **输出**：段落、表格、字段、顺序和格式。
5. **验收与停止**：怎样算完成，证据不足时如何标记，什么时候询问或停止。

### 第三部分：Skill 把一次成功变成可复用过程

Skill 最小结构包括可发现的名称和触发描述、任务说明、参考资料、确定性脚本、输出合同、异常处理、停止条件和版本。课堂展示一个会议行动项 Skill，以及同一模型上“模糊基线 1/4、Skill 4/4”的本地教学快照；同时说明样本只有四个，授权案例由运行器在模型前停止，不能外推生产准确率。

### 第四部分：先诊断失败，再升级技术

问题诊断顺序：

1. 任务是否说清楚？没有就改 Prompt。
2. 是否缺少最新或内部事实？是则使用受控检索/RAG。
3. 是否必须读取系统或执行动作？是则连接获准工具。
4. 是否为稳定、重复的同类流程？是则封装 Skill 或固定工作流。
5. 步数是否不可预知且需要动态选择工具？满足时才考虑 Agent。
6. 代表性评测上是否仍有稳定行为缺口？满足时才评估微调。
7. 是否需要广泛新基础能力？这才进入预训练问题。

## 两次课堂互动

### 互动一：缺了什么

屏幕显示：“请把下面会议内容整理成一份专业周报。”

让听众在十秒内指出缺项。标准答案不是某一句固定话术，而是目标读者、事实来源、输出结构、未知信息处理和验收标准中的任意两项。

### 互动二：选哪一层

题目：“每周都要把会议记录整理成同一格式，而且负责人或截止日期缺失时不得猜。优先改什么？”

答案：先把输出合同和缺失值规则写清，并封装为 Skill/固定工作流；如果还要从内部系统读取最新项目状态，再增加获准检索或工具。不能直接回答“微调”。

## 讲授成功标准

- 听众能够复述五字段，不要求记住每个英文缩写。
- 听众能把至少一个真实工作任务映射到 Prompt 或 Skill。
- 听众知道不能把敏感信息随意交给未获准工具。
- 听众能够解释“评测先于升级”。
- 课程在真实彩排中保持 18–20 分钟；自动估时只用于发现明显偏差。
