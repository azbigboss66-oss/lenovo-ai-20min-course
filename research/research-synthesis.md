# 研究综述：面向联想资深在职初学者的 20 分钟 AI 课程

## 研究结论

20 分钟只能建立一个可迁移的工作模型，不能完成完整人工智能通识教育。最有效的课程主线不是依次解释模型、Prompt、RAG、Agent、Skill 和微调，而是让同一个工作任务经历四次升级：理解模型的能力边界，把模糊请求写成 Prompt，把反复成功的做法封装为 Skill，再通过评测决定是否增加知识、工具或参数层定制。

这条主线同时覆盖 UNESCO 人工智能能力框架中的“理解、应用、创造”三个进阶层次，以及以人为本、伦理、技术应用和系统设计四个维度。[1] 对在职听众而言，课程目标应定位为 AI literacy：能够理解、使用、监控并批判性判断 AI 应用，不要求每个人都能开发模型。[22]

## 1. 初学者需要的准确心智模型

OECD 将 AI 系统定义为一种机器系统：它从收到的输入中推断如何生成预测、内容、建议或决策等输出，并以不同程度的自主性和部署后适应性运行。[2] 这个定义比“像人一样思考的机器”更适合企业课程，因为它让听众关注输入、输出、影响和责任。

大语言模型把文本拆成 token，根据上下文估计下一个 token 或 token 序列的概率。Transformer 的自注意力机制使模型能够衡量上下文中不同 token 之间的关系。[3][4] 因此模型可以生成流畅文本，但流畅不是事实证明。NIST 将模型有把握地产生错误或虚假内容称为 confabulation，并把它列为生成式 AI 的重要风险。[5]

适合课堂的类比是“能力很强、读过大量材料、擅长续写的同事”。Prompt 像本次工作委托，RAG 像临时交给他的最新资料，工具像他可调用的计算器和业务系统，Skill 像经过验证的标准作业包，评测像验收清单，微调像用大量示例调整稳定习惯。类比讲完必须回到技术定义，以免听众误以为模型拥有人的理解、责任或数据库式记忆。

## 2. Prompt 的核心不是咒语，而是任务合同

当前官方提示工程材料反复强调清楚的目标、相关上下文、输出要求和示例；Few-shot 是在上下文中给出少量输入输出范例，而不是修改模型参数。[6] 因此课程采用“五字段法”作为记忆框架：目标、必要上下文、约束、输出、验收与停止条件。它是课程设计，不是行业唯一标准。

角色设定可以统一语气或视角，却不能替模型补充事实。对于联想工作环境，最重要的 Prompt 改进往往不是“你是一位世界级专家”，而是提供原始记录、说明只依据材料、标出缺失信息、规定输出字段并写明谁来确认。若任务需要最新或内部事实，单纯延长 Prompt 不能替代受控检索。[6][13]

## 3. Skill 是过程资产，不是超长 Prompt

开放 Agent Skills 规范以一个目录为基本单元，要求 `SKILL.md`，并允许增加 `scripts/`、`references/` 和 `assets/`。规范采用渐进式披露：先让系统看到名称和描述，触发后读取完整说明，需要时才加载脚本和参考资料。[8]

OpenAI 当前文档同样把 Skill 描述为“可版本化文件包加 `SKILL.md` 清单”，用于固化流程和约定。[7] 一个企业 Skill 至少要回答：何时触发、需要什么输入、按什么步骤执行、要读哪些受控资源、哪些检查由脚本完成、遇到什么情况停止、输出结构是什么、谁负责最终确认。

Skill 的价值需要比较证据。Agent Skills 的评测指南建议用真实感任务，覆盖边界情况，分别在有 Skill 和无 Skill 或旧版本条件下运行，使用可验证断言与人工审阅，同时记录时间和 token 成本。[10] 因此课堂不能说“写完 `SKILL.md` 就完成自动化”，只能说“形成了一个可进入 Agent 环境验证的候选过程包”。

## 4. Prompt、RAG、工具、Skill、Agent 和微调的边界

RAG 将参数化模型与外部非参数记忆结合，为知识密集任务提供可更新资料和来源。[13] 工具则让系统读取外部状态或执行真实动作。ReAct 研究展示了把推理与行动交错，使模型通过外部知识库或环境获取信息的基本模式。[12]

工作流和 Agent 也应区分。预定义代码路径更适合稳定、可预测的流程；Agent 让模型动态决定步骤和工具，更灵活，但带来成本、延迟和误差累积。工程经验建议先从简单、可组合的方案开始，只有结果得到可测量改善时才增加复杂度。[11]

建议的课堂诊断表如下：

| 观察到的问题 | 优先手段 | 原因 |
|---|---|---|
| 单次请求目标含糊 | Prompt | 最低成本地澄清任务合同 |
| 缺少最新、内部或指定来源事实 | RAG/检索 | 在请求时补充可更新的外部知识 |
| 必须读取系统或执行动作 | 工具 | 文字生成本身不能完成真实操作 |
| 同类任务需要反复按统一过程完成 | Skill/固定工作流 | 固化步骤、资源、检查和停止条件 |
| 步数不可预知且需要动态选择工具 | Agent | 允许在反馈循环中规划和调整 |
| 稳定行为在大量代表性样例上仍不达标 | 微调 | 用训练示例改变参数层面的行为倾向 |
| 要形成广泛的新基础能力 | 预训练 | 涉及大规模数据、模型与计算工程 |

所有技术选择之前都要定义代表性样例和验收标准。OpenAI 的模型优化材料将评测、Prompt 和微调描述为循环，并明确要求使用代表真实输入的测试数据。[14] 这是一项通用工程原则；同一页面在 2026 年又包含厂商平台调整信息，因此课程只引用方法论，不把具体平台可用性写成长久事实。

## 5. 微调与预训练应该怎样“升维”

监督微调使用任务输入和理想输出示例调整模型行为。InstructGPT 研究展示了用人工示范和偏好数据改善指令遵循，但论文也明确模型仍会犯简单错误。[15] LoRA 冻结基础权重，用低秩矩阵学习较小的权重更新，从而减少可训练参数和内存需求；这降低的是适配成本，不消除数据质量、验证、隐私和回归风险。[16][17]

预训练解决的是更广泛的能力形成。Chinchilla 研究说明模型规模、训练 token 和计算预算需要联合设计，而不是单纯把参数做大。[18] 因此 20 分钟课程不演示训练，只让听众看到“应用层、编排层、参数层、基础训练层”的位置关系。专业感来自知道证据和边界，而不是用最大的技术名词压轴。

## 6. 联想工作环境中的责任边界

联想公开的负责任 AI 材料提出六个支柱：多样性与包容、隐私与安全、问责与可靠、可解释、透明，以及环境与社会影响。[19] 对普通员工最可操作的转译是四个问题：这份输入可以交给当前获准工具吗；输出中的事实来自哪里；错误由谁发现和负责；这项任务能否留下版本、来源和检查记录。

课程案例不应包含真实客户、员工、设备序列号、价格、未公开路线图或内部制度原文。模拟案例只训练方法。如果实际任务涉及受限信息，应遵循公司当时有效的工具、数据和审批要求；公开教材不能替代内部政策。

## 7. 面向资深在职同事的教学设计

有经验的在职同事不是“零经验学习者”，他们拥有丰富业务图式，只是缺少 AI 术语和操作模型。National Academies 对终身学习和职场学习的综述强调学习环境、主动参与、训练迁移和工作情境。[24] 因此课程应尊重其业务判断，避免幼稚化比喻，并把抽象概念持续映射到会议、项目、客户问题和资料检索。

认知负荷研究支持先看完整示例，再让初学者独立解决问题。[26] ICAP 框架则把参与方式从被动、主动、建构到互动区分开来，并预测更深参与带来更好的学习。[25] 20 分钟内最现实的活动是两次短判断：第一次找出模糊 Prompt 缺了什么，第二次判断新任务应选 Prompt、RAG、工具、Skill 还是微调。

PPT 采用 assertion–evidence 方法：标题直接表达完整结论，用对比、流程图、结构图和决策矩阵提供视觉证据，而不是在屏幕上复制讲稿。[27]

## 8. 研究停止条件与限制

关键课程结论已经覆盖国际组织、政府框架、原始论文、开放规范、厂商一手文档、联想公开材料和学习科学来源。后续继续搜索更多博客或视频不太可能改变课程结构，因此停止扩展来源。

仍有三项限制。第一，不同模型和企业工具的实际能力、权限与数据政策会变化，正式授课前应核对联想当时批准的工具和内部要求。第二，自动字符估时不是现场彩排。第三，示例 Skill 只验证结构和确定性输出合同，不构成真实 Agent 环境或生产效果证明。
