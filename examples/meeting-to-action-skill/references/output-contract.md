# 输出合同

## 必需结构

输出按以下顺序包含四个二级标题：

1. `## 本次结论`
2. `## 风险与影响`
3. `## 行动项`
4. `## 待确认事项`

## 行动项表

表头必须正好为：

```markdown
| 事项 | 负责人 | 截止日期 | 原文依据 | 状态 |
|---|---|---|---|---|
```

字段规则：

| 字段 | 合同 |
|---|---|
| 事项 | 使用动作动词，描述一个可完成的结果；不能把讨论主题当作行动。 |
| 负责人 | 只写会议记录明确给出的人或角色；否则写 `未提供`。 |
| 截止日期 | 保留原文的绝对或相对日期；否则写 `未提供`。 |
| 原文依据 | 写能定位该行动的简短原文片段；不得写 `未提供`。 |
| 状态 | 只采用原文明示的 `已完成`、`进行中`、`未开始` 或 `待确认`；否则写 `未提供`。 |

## 事实边界

- 计划、建议和假设不能写成已经决定的事实。
- 相对日期只有在参考日期明确且用户要求转换时才能换成绝对日期。
- 同一事项出现矛盾负责人或日期时，表中写 `待确认`，并在“待确认事项”保留冲突双方的原文依据。
- 不扩写客户身份、设备标识、财务数据、未公开计划或因果结论。

## 人工验收

机械检查通过后，会议参与者仍需确认：结论是否遗漏关键决策；行动是否真实存在；负责人和日期是否准确；内容是否适合目标读者和传播范围。
