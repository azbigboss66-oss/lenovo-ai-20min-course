# 输出合同

## 必需结构

输出按以下顺序包含四个二级标题：

1. `## 本次结论`
2. `## 风险与影响`
3. `## 行动项`
4. `## 待确认事项`

如果输入授权状态不明确，不生成上述四段结构，仅返回：

`未处理：当前材料的使用授权尚未确认。请提供获准的教学模拟或脱敏版本后再继续。`

## 行动项表

表头必须正好为：

```markdown
| 事项 | 负责人 | 截止日期 | 原文依据 | 状态 |
|---|---|---|---|---|
```

字段规则：

| 字段 | 合同 |
|---|---|
| 事项 | 使用动作动词，描述一个可完成的结果；不能把讨论主题当作行动。 |
| 负责人 | 只写会议记录明确给出的人或角色；否则写 `未提供`。 |
| 截止日期 | 完整保留原文的绝对或相对日期及“前、后、左右”等限定词；行动句中的时间用于该行动，即使另一项后续里程碑日期缺失；否则写 `未提供`。 |
| 原文依据 | 写能定位该行动的简短原文片段；不得写 `未提供`。 |
| 状态 | 只采用原文明示的 `已完成`、`进行中`、`未开始` 或 `待确认`；否则写 `未提供`。 |

## 事实边界

- 计划、建议和假设不能写成已经决定的事实。
- 相对日期只有在参考日期明确且用户要求转换时才能换成绝对日期。
- 同一事项出现矛盾负责人或日期，且原文明确没有最终结论时，表中的争议负责人、日期和状态都写 `待确认`，并在“待确认事项”保留冲突双方的原文依据。
- 不扩写客户身份、设备标识、财务数据、未公开计划或因果结论。
- 行动项必须来自原文明确的请求或承诺。仅仅“值得做”不等于会议已经形成行动项。
- 原文依据使用可在输入中逐字定位的短片段，便于确定性检查和人工回看。

## 人工验收

机械检查通过后，会议参与者仍需确认：结论是否遗漏关键决策；行动是否真实存在；负责人和日期是否准确；内容是否适合目标读者和传播范围。

教学标准答案位于 `../examples/`。它们只定义本课程四个模拟场景的验收结果，不构成真实联想流程或模型通用准确率证明。
