# 联想工作场景迁移练习

> 教学模拟：本文件中的客户、产品线、项目、故障、系统和流程均为虚构。练习训练的是任务分析方法，不代表联想真实制度、产品参数或生产流程。

## 案例一：客户问题升级摘要

### 情境

一位项目经理收到多轮邮件，需要向支持负责人说明“客户 A 的一批教学终端在系统更新后出现间歇性外接显示异常”。邮件中有人提出驱动、线材和扩展坞三个可能方向，但尚无根因结论。

### 容易犯的错

直接要求模型“写一封专业升级邮件”，模型可能把假设改写成已确认根因，或把讨论中的时间变成服务承诺。

### 五字段 Prompt

```text
目标：把 <emails> 整理成给支持负责人的问题升级摘要，帮助其决定下一步排查。
上下文：只使用所给邮件；客户统一称“客户 A”；材料为教学模拟。
约束：区分已确认事实、待验证假设和请求；不得宣布根因，不得承诺未确认时限。
输出：现象、影响范围、已完成检查、假设与证据、待支持事项、行动项表。
验收/停止：每个根因表述必须标注“已确认”或“待验证”；缺设备标识、日志或复现条件时列入信息缺口；材料为空时停止。
```

### 技术选择

- 只有邮件整理：Prompt 足够。
- 需要查询最新公开排障资料：增加受控检索。
- 需要读取工单状态或日志：连接获准工具。
- 同类升级每周大量发生：把字段、检查和停止条件封装为 Skill/工作流。
- 不应把微调作为第一步，因为当前主要缺口是事实与流程，而非稳定行为模式。

## 案例二：产品资料对比

### 情境

销售支持同事收到三份经批准的公开产品材料，希望制作客户沟通前的差异表。材料版本日期不同，某个端口规格在两份材料中不一致。

### 容易犯的错

模型可能依据训练记忆补参数，把较新的资料默认当作绝对正确，或者在冲突处选择一个更“合理”的值。

### 五字段 Prompt

```text
目标：根据指定资料生成产品 A、B、C 的客户沟通前差异表。
上下文：只允许使用 <approved_sources> 中的三份材料，并保留文档名与版本日期。
约束：不得使用模型记忆补参数；冲突值并列展示；不做未经材料支持的推荐。
输出：特性、A、B、C、来源、差异说明、待确认六列；表后列出资料版本风险。
验收/停止：每个规格必须有来源；同一规格冲突时标记“冲突待确认”；关键资料打不开时停止该项结论。
```

### 技术选择

如果资料每次随请求提供，Prompt 加上下文即可。如果资料库持续更新、需要按权限检索和保留引用，应使用 RAG/企业搜索。若还要把结果写入客户关系系统，则需要经授权的工具和提交前确认。

## 案例三：内部制度问答

### 情境

一位同事问：“出差改签能不能报销？”正确答案取决于地区、员工类型、费用原因和当前制度版本。

### 容易犯的错

模型可能凭常识生成一套听起来合理的政策，也可能引用已经失效的版本。这个任务的核心不是语言表达能力，而是权威资料、版本、权限和引用。

### 五字段 Prompt

```text
目标：基于获准制度库回答报销条件，并帮助提问者找到下一步。
上下文：检索时只使用当前用户有权访问且处于有效期的制度文件。
约束：不得用常识补制度；不输出用户无权访问的内容；不代替财务审批。
输出：简短结论、适用条件、证据引用、仍需确认的信息、办理入口。
验收/停止：结论必须含制度标题、版本或生效日期和具体条款；无权威命中或条款冲突时回复“无法确认”，转人工渠道。
```

### 技术选择

这里优先建设带权限、版本和引用的检索能力，而不是把制度“训练进模型”。制度更新时，RAG 可以替换资料；微调参数不会自动同步新政策，也不天然提供可核验出处。

## 案例四：会议行动项 Skill 候选

### 什么时候值得封装

- 每周或每个项目都执行相似步骤。
- 输入形式相对稳定，例如会议记录或转录文本。
- 输出必须遵守共同字段和缺失值规则。
- 人工修改中反复出现相同问题。
- 能准备代表性样例并比较有 Skill 与无 Skill 的结果。

### 什么时候暂不封装

- 任务只发生一次。
- 团队尚未形成共同流程，成功标准仍在争议。
- 输入包含尚未解决的授权或隐私问题。
- 输出不能被可靠验收，只有“感觉不错”。

## 课堂讨论答案

| 问题 | 推荐起点 | 判断依据 |
|---|---|---|
| 邮件太杂，先生成结构化摘要 | Prompt | 目标和格式问题可在单次请求内解决 |
| 需要最新产品资料和出处 | RAG/检索 | 知识需要更新和引用 |
| 需要读取工单、日志或写入系统 | 工具 | 涉及外部状态和真实动作 |
| 每周相同字段、相同检查 | Skill/固定工作流 | 需要复用过程与合同 |
| 步数不可预知、需动态排查 | Agent | 需要在反馈中自主选步骤与工具 |
| 大量评测中仍稳定不遵守目标格式 | 评估微调 | 参数层行为缺口已有证据 |
| 希望建立全新通用模型能力 | 预训练 | 需要大规模数据和算力工程 |

## 业务边界口诀

- **可交**：输入可以交给当前获准工具吗？
- **可证**：关键事实有可访问的来源吗？
- **可责**：谁复核，谁作最终决定？
- **可追**：使用的资料、版本和检查结果能追溯吗？
