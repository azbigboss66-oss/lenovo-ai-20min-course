# 联想在职同事 AI 入门课程教材仓库设计

## 目标

交付一个独立 Git 仓库，供讲师准备和讲授约 20 分钟的人工智能入门课程。课程面向工作经验丰富、但刚接触生成式人工智能的联想同事。教材必须有实际工作价值，不能停留在术语介绍，也不能把未经确认的联想内部制度、产品流程或客户数据写成事实。

课程完成后，听众应能：

1. 用自己的话解释生成式人工智能和大语言模型为何既有用又会犯错。
2. 把一个模糊工作请求改写成包含目标、上下文、约束、输出和验收条件的 Prompt。
3. 说明 Prompt、Skill、知识检索、工具调用、微调和预训练分别解决什么问题。
4. 为一个重复性联想工作任务画出 Skill 的最小结构，并指出人工复核与停止条件。
5. 用“先评测、再升级”的方法选择技术路径，而不是把模型训练当作默认答案。

## 课程叙事

课程采用“从一次请求到可复用工作能力”的单线叙事。主案例是跨部门项目会议后的周报和行动项整理：先展示一句模糊请求，再逐步补全 Prompt；随后把稳定做法封装为 Skill；最后遇到最新资料、系统操作或稳定行为缺口时，分别引出 RAG、工具和微调。

补充案例包括客户问题升级、产品资料检索和内部制度问答。所有案例均使用模拟输入，并在材料中明确标注“教学模拟”。涉及真实制度、产品参数、客户信息或内部系统行为的地方只讲方法，不编造事实。

## 20 分钟结构

| 时间 | 教学段落 | 核心产出 |
|---|---|---|
| 0:00–2:00 | 开场对比 | 听众看到模糊请求与结构化 Prompt 的结果差异 |
| 2:00–5:30 | AI 与大语言模型 | 建立“概率生成而非事实数据库”的准确心智模型 |
| 5:30–10:30 | Prompt 五字段法 | 完成主案例 Prompt 的逐步改写 |
| 10:30–15:30 | 从 Prompt 到 Skill | 理解可复用流程包、资源、脚本、异常和停止条件 |
| 15:30–18:30 | 升级路径 | 用问题诊断表区分 Prompt、RAG、工具、Skill、微调和预训练 |
| 18:30–20:00 | 收束与检查 | 完成一次口头判断题并记住“先评测，再升级” |

讲稿目标长度为 4,200–4,800 个中文字符。自动估时只作为预警；最终时长结论必须标记为“需讲师按实际语速彩排确认”。

## 内容设计

### AI 基础

只保留能够支撑后续判断的概念：AI 系统、大语言模型、token、上下文、概率生成、Transformer、自注意力和幻觉。技术解释采用工作类比，但每个类比之后必须回到准确术语和能力边界。

### Prompt

使用课程自定义的“五字段法”：任务目标、必要上下文、约束条件、输出格式、验收与停止条件。文中必须说明这是一种便于记忆的教学模板，而不是宣称为唯一行业标准。示例不得依靠“你是世界顶级专家”之类角色话术制造虚假确定性。

### Skill

Skill 被定义为可版本化、可复用的任务过程包，而不是长 Prompt。示例 Skill 包含触发条件、输入要求、执行步骤、引用资料、确定性检查脚本、异常处理、停止条件和输出合同。课程必须区分概念性 Skill 文件与实际 Agent 运行环境；不能暗示只写一个 `SKILL.md` 就获得了自动执行、权限管理和评测能力。

### 专业升维

以“评测驱动的 AI 能力工程”收束。诊断顺序为：先定义成功样例和失败模式，再判断修改 Prompt、补充检索、调用工具、固化 Skill 或做参数层定制。微调与 LoRA 作为参数层方案介绍；预训练仅解释其位置、数据与算力规模，不安排课堂操作演示。

## 研究策略

资料优先级为：国际组织与政府框架、开放规范、原始论文、官方技术文档、大学教学方法。关键结论至少由一项一手来源支持；产品特定内容必须标注访问日期。来源台账记录标题、机构或作者、日期、URL、用途和适用边界。

重点研究问题：

1. 如何给非技术在职听众建立准确而不过载的 AI 心智模型？
2. Prompt 的有效组成部分有哪些，哪些流行说法证据不足？
3. Skill 的规范结构、渐进式披露和评测方法是什么？
4. Agent、工作流、RAG、工具、微调与预训练的边界如何用一个决策框架解释？
5. 20 分钟课程如何兼顾知识密度、案例练习与专业深度？

## 验证设计

本项目不采用严格 TDD。交付物以内容研究、教学设计和文档为主，验证方式按声明选择：

- 事实准确性：逐条核对来源台账，区分原始事实、分析判断和教学建议。
- 链接有效性：脚本检查所有 Markdown URL 格式，并对关键链接进行联网复核。
- 时长：字符数估算加段落预算检查，结论保留人工彩排要求。
- 仓库完整性：脚本检查必需文件、标题、模拟案例标记和禁止占位符。
- Skill 示例：运行确定性检查脚本的正常样例与缺字段样例，验证输出合同，而不声称测试了真实联想系统。
- 教学适切性：按受众、难度、工作相关性、认知负荷、例子一致性和专业收束逐项人工复核。
- 自检报告：记录通过项、限制和正式授课前仍需讲师确认的事项，禁止使用笼统的“全部通过”。

## 不在范围内

- 不制作或引用视频。
- 不制作最终 `.pptx`，但提供可直接转制的逐页 PPT 内容和讲者备注映射。
- 不接入联想内部系统，不使用真实员工、客户、设备、项目或未公开制度数据。
- 不宣称课程中的模拟 Skill 已经在生产环境部署。
- 不进行模型微调、预训练或厂商产品现场操作。

## 完成标准

仓库必须包含完整讲稿、分钟级大纲、PPT 页纲、讲师指南、工作速查表、联想工作场景案例、Skill 示例、研究综述、来源台账和自检报告。所有材料内部术语一致，无 `TODO`、`TBD` 或空白章节；Git 工作区干净并至少包含一个完整内容提交。
