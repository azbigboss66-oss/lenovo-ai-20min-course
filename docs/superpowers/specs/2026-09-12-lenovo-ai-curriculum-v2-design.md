# 联想 AI 工作方法系列课 V2 设计规格

## 1. 目标与边界

本次交付以七节连续课程替换原单课教材。受众仍是工作经验丰富、熟悉业务协作、但刚接触生成式 AI 的联想同事。每节 15–30 分钟，能够独立讲授，也能按顺序组成约 180 分钟的课程链。

课程不能只是公开资料的拼接或 AI 功能清单。它以“AI 能力的分水岭，是能否把判断、证据、边界和改进设计进工作系统”为总论，并用五项讲师判断贯穿七课。来源用于校准事实，教学取舍必须由讲师能够解释和接受质疑。

最终交付包括：课程总纲、七节详细中文讲稿、七套课堂练习与参考答案、可离线打开并可部署到 GitHub Pages 的 HTML 教材、可复用 Skill 示例、研究台账和自检证据。

明确边界：

- 不接入联想内部系统，不使用真实员工、客户、设备、项目、价格、路线图或内部制度数据。
- 所有联想工作案例必须标注“教学模拟”。
- 不把四个模拟案例的本地模型对照结果外推为生产效果或通用准确率。
- 不把 `SKILL.md` 等同于已经部署的业务能力；运行选择、权限、工具、追踪和评测属于运行环境责任。
- 不在课程中现场执行微调或预训练，只解释选择条件、数据要求、风险与评测闭环。
- 公开教材不能替代联想当时有效的内部数据、工具、合规、品牌和审批规则。

## 2. 课程能力链

课程不按术语堆叠，而按工作能力递进：

1. **判断**：理解 AI、生成式 AI 和大语言模型的能力边界。
2. **委托**：把模糊要求写成可验收 Prompt。
3. **求证**：区分模型参数记忆、上下文和受控检索，建立证据链。
4. **固化**：把一次成功沉淀为有触发、资源、步骤、停止和评测的 Skill。
5. **编排**：区分工具、固定工作流和 Agent，并设置权限与人工确认点。
6. **评测**：用代表性样例判断应优化 Prompt、RAG、工具、Skill、微调还是预训练。
7. **落地**：完成一个“可交付、可证明、可追责、可追踪”的联想工作模拟闭环。

## 3. 七节课程

| 编号 | 课程 | 计划时长 | 联想工作模拟 | 可观察产出 |
|---|---|---:|---|---|
| 01 | AI 从零开始 | 20 分钟 | 把跨部门会议记录整理为管理摘要 | AI 适用性判断卡 |
| 02 | Prompt：把要求写成工作合同 | 25 分钟 | 把一句模糊周报请求改写成五字段委托 | 一份 Prompt 合同 |
| 03 | 证据、数据与 RAG | 25 分钟 | 根据产品资料回答差异问题并标注出处 | 一张答案证据表 |
| 04 | Skill：把一次好结果变成能力 | 27 分钟 | 会议记录转行动项 | 一个可评测 Skill 包 |
| 05 | 工具、工作流与 Agent | 25 分钟 | 读取工单与日志后草拟状态通知，提交前停下 | 权限与人工审批图 |
| 06 | 评测与模型升级路线 | 28 分钟 | 用冻结案例比较基线和 Skill 版本 | 技术选择矩阵与评测计划 |
| 07 | 联想场景综合实战 | 30 分钟 | 从会议输入到任务清单、证据、风险和复盘 | 一套经审计的 AI 工作流 |

每节采用同一学习节奏：问题切入 → 心智模型 → 错误示范 → 完整示例 → 3–5 分钟练习 → 参考答案与评分 → 岗位迁移。每节只要求学员带走一个主要方法和一个可观察产出。

## 4. 内容源与 HTML 架构

采用“内容源优先”的静态教材架构：

- `curriculum/` 保存总纲、讲师运行手册、课程地图和术语表。
- `lessons/01-*` 至 `lessons/07-*` 各保存 `outline.md`、`speaker-script.md`、`exercise.md` 和 `reference-answer.md`。
- `examples/` 保存跨课复用的模拟输入、Prompt、Skill、评测样例与证据。
- `site/` 保存可直接双击打开的 HTML、CSS、JavaScript 与官方品牌资产。
- `scripts/build_site.py` 从课程元数据和 Markdown 内容生成 HTML，减少讲稿与网页漂移。
- `scripts/check_curriculum.py` 检查结构、时长、模拟标记、来源、HTML 导航和术语边界。

生成器只负责确定性排版，不把生成 HTML 本身当成内容质量证明。内容质量还需事实审校、课堂适切性审校和真人彩排。

## 5. HTML 信息架构

### 5.1 总览页

首页第一屏包含课程名称“AI 工作新方法”、副标题“从会使用，到会设计、会验证”、开始按钮与五步工作流程。第二段采用纵向七课路径，不使用重复的卡片宫格。末段展示“可交付、可证明、可追责、可追踪”四项原则。

### 5.2 单课页

单课页采用三栏结构：左侧课程导航、中间教学正文、右侧分钟时间线。正文支持复制提纲、显示/收起参考答案、讲师模式、上一课/下一课和本地进度。移动端折叠为单栏，导航变为顶部可横向滚动的课程链接，正文仍保持可读顺序。

### 5.3 交互边界

所有交互均为本地状态：复制文本、展开答案、讲师备注、课程进度与导航。教材不调用外部 AI API，不收集或上传学习者数据。`localStorage` 只保存页面上的完成状态和讲师模式偏好。

## 6. 视觉与品牌系统

设计基准：

- [课程总览页视觉概念](../../design/course-home-concept.png)
- [单课页视觉概念](../../design/lesson-page-concept.png)

> 上述概念图只定义版式、信息密度和色彩关系，不作为网页中的图片组件，也不包含生成式 Lenovo Logo。

视觉令牌：

- 真白背景 `#FFFFFF`；正文近黑 `#111111`；次级文字 `#5B616B`；浅灰面 `#F3F4F5`；分隔线 `#D9DDE1`。
- 主强调色采用 Brand World 官方资源中的 signature red 视觉，CSS 近似值为 `#E2231A`；Logo 本体不得改色。
- 标题使用系统无衬线字体栈，优先 `Arial, Helvetica, "PingFang SC", "Microsoft YaHei", sans-serif`；不随仓库分发未授权企业字体。
- 方正、低圆角、1px 规则线、克制阴影；禁止紫蓝渐变、光晕、AI 机器人、装饰电路、胶囊标签和默认卡片宫格。

Logo 使用 Lenovo Brand World 页面提供的官方横版红底白字资源，保留 3:1 比例、至少 100px 数字宽度和规定留白。在静态页面右侧边缘定位。课程页概念图原先把 Logo 槽放在左侧，但 Brand World 当前明确建议静态应用放在右侧，因此正式实现以品牌规范为准；这是记录过的有意偏差。

页面页脚包含商标归属与“内部教学候选材料，使用前需按当前内部规范复核”的说明。

## 7. 课程事实与来源策略

来源优先级为国际组织/政府框架、原始论文、开放规范、厂商一手文档和联想公开材料。课程对标 Google AI Essentials、Microsoft Generative AI for Beginners、OpenAI Academy、IBM SkillsBuild、Elements of AI、OECD AI literacy、NIST AI RMF 与 Lenovo Brand World。

引用采用两级方式：讲稿正文只保留会影响理解和风险判断的简短来源编号；每课末尾列出具体来源，`research/sources.md` 保存完整链接、访问日期、用途和适用边界。产品界面和厂商能力均标注可能变化。

## 8. 验收设计

本项目不采用严格 TDD；验证方式按声明选择：

- **结构合同**：脚本检查七课、每课四类材料、HTML 页面、导航、官方 Logo 文件和无未完成占位符。
- **时长预警**：按讲稿可讲文本、互动预算和 210/230/250 等效字符每分钟生成估时；15–30 分钟为自动门禁，真实时长仍需讲师彩排。
- **Skill 契约**：运行现有确定性检查、四个参考答案和已保存本地模型对照；只证明课堂模拟证据。
- **事实与教学适切性**：逐课人工检查术语、来源、难度、案例完整性、隐私边界和可观察产出。
- **HTML 静态/浏览器检查**：生成后检查本地链接、HTML 标题、语义结构、复制/展开/进度交互，以及桌面和移动布局。
- **视觉忠实度**：对比概念图和浏览器截图，记录至少五项版式、字体、色彩、资产、留白和响应式差异。
- **远端完整性**：推送新分支、创建 Pull Request 后，在 GitHub/Edge 验证文件清单和 PR 状态；合并由用户决定。

## 9. 完成判定

只有七节课程、详细讲稿、练习与答案、HTML 教材、官方 Logo、研究台账、自检报告、浏览器证据和 GitHub Pull Request 均存在且相互一致时，才可称为交付完成。自动检查不能证明真人授课效果、内部审批或生产可用性；这些限制必须留在最终报告中。
